# Volume group snapshots: crash-consistent snapshots of multiple volumes

## Problem

Dell's CSM drivers support Volume Group Snapshots — crash-consistent snapshots of multiple volumes simultaneously, coordinated at the storage array level. TrueNAS supports this natively: create a TrueNAS snapshot task that spans multiple datasets in a single atomic operation.

Our CSI spec only includes single-volume snapshot support (S-11). For workloads like a database with separate PVCs for data, WAL, and logs, a separate snapshot of each PVC might capture inconsistent state if the writes happen in a different order on each PVC. A volume group snapshot ensures all PVCs are snapshotted at the same point in time across the TrueNAS backend.

## Design

The CSI Volume Group Snapshot API (CSI spec 1.11) defines three types:
- `STAGE` — only the PVCs' staged volumes are snapshotted (controller-only, the volumes aren't yet published to pods)
- `READY` — all PVCs have staged AND published volumes snapshotted (the pods are running, so the volumes are in-use — this is the typical case where TrueNAS's snapshot capability matters)
- `UNSTAGE` — the StageSnapshots are deleted after the controller snapshots them

For TrueNAS, a volume group snapshot is a dataset snapshot created with multiple datasets:

```
pool/home/volume1/@snap1
pool/home/volume2/@snap1
pool/home/volume3/@snap1
```

All three datasets share the same snapshot name `@snap1`, making them a crash-consistent group. TrueNAS snapshots all datasets in the group atomically (at the ZFS level).

### TrueNAS API

TrueNAS supports multiple dataset snapshots in a single task:

```go
// PoolDatasetCreateSnapshotRequest supports multiple snapshots
type PoolDatasetCreateSnapshotRequest struct {
    Dataset        []string  // multiple datasets to snapshot atomically
    Name           string    // shared snapshot name
    Recursive      bool      // include all children
    CustomProperties []PoolDatasetCreateSnapshotCustomPropertiesCustom  // user_properties
}
```

TrueNAS already supports creating a dataset-level snapshot that covers multiple datasets:
- Create multiple snapshots with the same name -> TrueNAS batches them into a single task
- All snapshots share the same creation transaction group (`createtxg`), providing crash-consistency

### Volume Group Snapshot Class

A `VolumeGroupSnapshotClass` defines the snapshot group policy:

```yaml
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeGroupSnapshotClass
metadata:
  name: truenas-vgsnap-class
driver: truenas.csi.watteel.com
parameters:
  volumesFrom:
    - selector:
        matchLabels:
          group: webapp
```

### Group Snapshot API

TrueNAS dataset snapshots are created by dataset name. A volume group maps to multiple datasets. The implementation:

1. For each PVC in the `VolumeGroupSnapshotClass`:
   - Resolve the PV's volume ID (our internal ID from the `truenas.csi.watteel.com/volume` label)
   - Resolve the dataset name from that volume ID
2. Create a single TrueNAS snapshot task containing all datasets:

```go
func (c *controller) CreateVolumeGroupSnapshot(ctx context.Context, req *csi.CreateVolumeGroupSnapshotRequest) (*csi.CreateVolumeGroupSnapshotResponse, error) {
    // 1. Resolve all datasets from the volume group spec
    var datasets []string
    for _, ds := range req.GetSource().GetVolumeHandles() {
        volume, err := c.backend.Volume(ctx, ds)
        if err != nil {
            return nil, status.Errorf(codes.NotFound, "volume %s not found", ds)
        }
        datasets = append(datasets, volume.DatasetPath)
    }

    // 2. Create a TrueNAS snapshot task for all datasets
    taskName := fmt.Sprintf("csg-%d", time.Now().UnixNano())
    _, err := c.client.PoolDatasetCreateSnapshot(ctx, &PoolDatasetCreateSnapshotRequest{
        Dataset:   datasets,
        Name:      taskName,
        Recursive: false,
    })

    // 3. Return the group snapshot response
    return &csi.CreateVolumeGroupSnapshotResponse{
        VolumeGroupSnapshot: &csi.VolumeGroupSnapshot{
            VolumeGroupSnapshotId: taskName,
            Source: &csi.VolumeGroupSnapshotSource{
                VolumeHandles: req.GetSource().GetVolumeHandles(),
            },
            CreationTime:  protoTimestamp(time.Now()),
            ReadyToUse:    true,  // TrueNAS snapshots are immediate (instantaneous)
        },
    }, nil
}
```

### Restore from Volume Group Snapshot

A volume group restore creates clones from multiple snapshots simultaneously, or creates them as separate volume group snapshots and then restores individually. TrueNAS clone creation is also atomic at the ZFS pool level.

### Volume Group Snapshot Restore

VolumeGroupSnapshotRestore can create a new VolumeGroup (new PVCs) from a snapshot group. This is the reverse of CreateVolumeGroupSnapshot — instead of creating snapshots from existing volumes, it creates new volumes from existing snapshots.

```go
func (c *controller) RestoreVolumeGroup(ctx context.Context, req *csi.RestoreVolumeGroupRequest) (*csi.RestoreVolumeGroupResponse, error)
```

`RestoreVolumeGroup` is a new CSI method that clones all volumes from their snapshots, returning the list of newly created volumes.

## Acceptance Criteria

- [ ] `TestCreateVolumeGroupSnapshot`: multiple volumes are snapshotted atomically with the same name on TrueNAS
- [ ] `TestCreateVolumeGroupSnapshotEmptyGroup`: an empty volume group returns an empty snapshot list (no error)
- [ ] `TestVolumeGroupSnapshotGrouped`: all snapshots in the group share the same `createtxg` (TrueNAS atomicity guarantee)
- [ ] `TestDeleteVolumeGroupSnapshot`: all snapshots in the group are deleted when the group is deleted
- [ ] `TestGetVolumeGroupSnapshot`: returning a VolumeGroupSnapshot by ID returns all the group's snapshots
- [ ] `TestRestoreVolumeGroup`: restores all volumes from the group snapshot with consistent timestamps
