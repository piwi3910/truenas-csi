PREREQUISITE — snapshots:
  This chart does NOT install the VolumeSnapshot CRDs or the snapshot
  controller, and `snapshotter.install` is false.

  The snapshot CRDs and the external-snapshotter controller are a cluster-wide
  singleton owned by the cluster, not by any one CSI driver. Two drivers
  installing them fight over the CRD version and break snapshots for every
  driver in the cluster. Install external-snapshotter once, yourself:

    https://github.com/kubernetes-csi/external-snapshotter

  Until it exists, VolumeSnapshot objects will not be served and the
  csi-snapshotter sidecar will log that it cannot find the CRDs. Everything
  else — provisioning, attaching, mounting, expansion — works without it.
{{- end }}

PREREQUISITE — node packages:
  The node plugin uses the host's storage tooling and advertises only the
  capabilities it can actually deliver. Missing packages, per protocol:

    iSCSI      open-iscsi        (iscsiadm, iscsid, iscsi_tcp)
    NFS        nfs-common        (mount.nfs)
    XFS        xfsprogs          (mkfs.xfs, xfs_growfs)
    SMB        cifs-utils        (mount.cifs)
    NVMe-oF    nvme-cli          (nvme, nvme_tcp)
    multipath  multipath-tools   (multipath, multipathd, dm_multipath)

  A StorageClass asking for something a node cannot do fails at
  NodeStageVolume with a message naming the missing package, rather than
  degrading silently. Multipath is the exception: it falls back to a single
  path and logs a warning.

  Check what each node found:

    kubectl -n {{ .Release.Namespace }} logs ds/{{ include "truenas-csi.fullname" . }}-node -c truenas-csi | grep capability

SECURITY NOTE — iSCSI:
  All volumes on a backend share one iSCSI target, and initiator ACLs are a
  property of the target, not of individual LUNs. Every node logged into the
  target can therefore see every LUN on it. ReadWriteOnce is enforced by
  Kubernetes, not below it. See docs/security.md.

SECURITY NOTE — NVMe/TCP:
  An NVMe subsystem is created OPEN (allow_any_host) unless the driver knows an
  initiator NQN to admit. Open means any initiator that can reach the portal may
  connect to that volume; there is no ACL to consult. Close it either way:
    * set `hostNQNs` on the StorageClass, or
    * annotate each node with its own host NQN, which the driver then admits:
        kubectl annotate node <node> \
          csi.truenas.watteel.com/nqn="$(cat /etc/nvme/hostnqn)"
  The equivalent iSCSI annotation is csi.truenas.watteel.com/iqn. Neither is set
  for you. See docs/security.md.
