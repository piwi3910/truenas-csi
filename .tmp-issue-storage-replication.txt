## Problem

Dell's CSM for Replication provides a generalized framework for storage array-based replication: `StorageProtectionGroup`, `failover`, `testfailover`, `failback`, `suspend`, `resume`, with a generic `CreateRemoteVolume` and controller-level coordination. TrueNAS has its own native replication feature (dataset replication to another TrueNAS appliance), but the CSI driver has no role in it — replication is entirely a platform concern managed via TrueNAS UI/API.

The CSI spec does not include replication APIs. Dell added them via the `dell/dell-csi-extensions/replication` proto, which defines a `Replication` service with protection group lifecycle management. TrueNAS has the underlying replication capability natively.

## Design

Create an `internal/storagereplication` package that implements the `Replication` proto against TrueNAS's replication API.

### StorageProtectionGroup

A `StorageProtectionGroup` represents a group of volumes (or a single volume) that are replicated to a remote TrueNAS appliance. The group provides:

- `Create` — create a TrueNAS replication task
- `Delete` — remove the replication task
- `Status` — query the replication task state (SUCCESS, WAITING, RUNNING, SUSPENDED)
- `ExecuteAction` — issue a replication action (failover, testfailover, failback, suspend, resume)

### TrueNAS Replication Tasks

TrueNAS replication works at the dataset level:

```
Pool0/home/volume1 -> (replication task) -> remote-truenas/Pool0/home/volume1
```

A replication task is created via:
- `data.repl_create_create` — creates a new replication task
- `data.repl_query` — query replication task state
- `data.repl_update` — update (e.g. to start/stop)
- `data.repl_delete` — delete the task

A task has:
- `parent_dataset` — source dataset
- `target_dataset` — destination dataset (must exist as clone)
- `host`, `port`, `destination_user`, `destination_ssh_key` — remote connection
- `direction` — PUSH or PULL
- `encryption` — optional
- `auto_destroy` — whether to auto-destroy the destination on failure

### Protection Group Implementation

```go
// StorageReplicator implements the Replication proto interface.
// Each protection group maps 1:1 to a TrueNAS replication task.
type StorageReplicator struct {
    client *truenas.Client
    config ReplicationConfig
}

type ReplicationConfig struct {
    RemoteHost string
    RemotePort int
    SSHKeyPath string
}

// GetStorageProtectionGroupStatus returns the state of the replication task.
func (r *StorageReplicator) GetStorageProtectionGroupStatus(ctx context.Context, req *replication.GetStorageProtectionGroupStatusRequest) (*replication.GetStorageProtectionGroupStatusResponse, error)

// CreateStorageProtectionGroup creates a TrueNAS replication task and returns the local/remote IDs.
func (r *StorageReplicator) CreateStorageProtectionGroup(ctx context.Context, req *replication.CreateStorageProtectionGroupRequest) (*replication.CreateStorageProtectionGroupResponse, error)

// DeleteStorageProtectionGroup destroys the replication task.
func (r *StorageReplicator) DeleteStorageProtectionGroup(ctx context.Context, req *replication.DeleteStorageProtectionGroupRequest) (*replication.DeleteStorageProtectionGroupResponse, error)

// CreateRemoteVolume creates a clone dataset on the remote TrueNAS appliance for the local volume.
func (r *StorageReplicator) CreateRemoteVolume(ctx context.Context, req *replication.CreateRemoteVolumeRequest) (*replication.CreateRemoteVolumeResponse, error)

// ExecuteAction performs a replication action (failover, testfailover, failback, failback discard, etc.)
func (r *StorageReplicator) ExecuteAction(ctx context.Context, req *replication.ExecuteActionRequest) (*replication.ExecuteActionResponse, error)
```

### Replication Task Mapping

| Replication Proto Action | TrueNAS API | Notes |
|-------------------------|-------------|-------|
| `CreateStorageProtectionGroup` | `data.repl_create` | Creates task + clones the destination dataset |
| `CreateRemoteVolume` | `pool.dataset.clone` + `data.repl_create` | Same as above, but on a different host |
| `DeleteStorageProtectionGroup` | `data.repl_delete` + `pool.destroy` | Destroys task + the cloned target dataset |
| `GetStorageProtectionGroupStatus` | `data.repl_query` + `data.repl_status` | Maps TrueNAS states to replication proto states |
| `ExecuteAction` | Varies | See mapping below |

### Action Mapping

| Replication Proto Action | TrueNAS Equivalent | Implementation |
|-------------------------|--------------------|----------------|
| `SUSPEND` | `UPDATE {"run_period": "00:00"}` | Set run period to 0 (disabled) |
| `RESUME` | `UPDATE {"run_period": "daily"}` | Restore regular schedule |
| `FAILBACK` | `data.repl_destroy` + recreate from target to source | Destroy old task + create reverse task |
| `FAILOVER_LOCAL` | N/A | No-op — the local dataset IS the active writer, nothing to do. Update the replication status to reflect local is now the source. |
| `FAILOVER_REMOTE` | Destroy local, promote remote clone, create new reverse replication | Kill the old task, destroy/replace the old local volume, set up reverse replication from remote |
| `TEST_FAILOVER` | Run the replication task manually, verify the clone works | One-shot replication + status check |
| `TEST_FAILOVER_STOP` | Stop test failover | Destroy the cloned dataset |

### State Mapping

| TrueNAS State | Replication Proto State | Notes |
|--------------|------------------------|-------|
| `SUCCESS` | `SYNCHRONIZED` | Replication completed successfully |
| `WAITING` | `SYNC_IN_PROGRESS` | Waiting for the next scheduled run |
| `RUNNING` | `SYNC_IN_PROGRESS` | Replication is in progress |
| `FAILED` | `SYNC_IN_PROGRESS` or `INVALID` | Failed — next successful run will sync |
| — | `SUSPENDED` | When run_period is 0 |
| — | `FAILEDOVER` | After a failover action |

### Controller Deployment

The replication proto service is registered alongside the CSI gRPC server in `internal/csi/controller.go`:

```go
func StartController(ctx context.Context, conn *truenas.Conn, cfg *config.Config, logger *slog.Logger, metrics *obs.Metrics) error {
    controller := New(cfg)
    listener, err := net.Listen("unix", socketAddress)
    if err != nil {
        return err
    }
    
    grpcServer := grpc.NewServer()
    serving.RegisterControllerServer(grpcServer, controller)
    replication.RegisterReplicationServer(grpcServer, storagereplication.New(conn, cfg))
    
    if err := grpcServer.Serve(listener); err != nil {
        return err
    }
    return nil
}
```

This means the replication proto is served from the same unix socket that the CSI controller uses — the replicator sidecar connects to the same unix socket and calls these methods.

## Acceptance Criteria

- [ ] `TestCreateStorageProtectionGroup`: calling CreateStorageProtectionGroup creates a TrueNAS replication task with correct parameters
- [ ] `TestGetStorageProtectionGroupStatusSynchronized`: a successful task returns `SYNCHRONIZED` state
- [ ] `TestGetStorageProtectionGroupStatusInProgress`: a running task returns `SYNC_IN_PROGRESS` state
- [ ] `TestGetStorageProtectionGroupStatusSuspended`: a task with run_period=0 returns `SUSPENDED` state
- [ ] `TestDeleteStorageProtectionGroup`: a replication task is deleted and the clone is destroyed
- [ ] `TestExecuteActionFailback`: executing failback destroys the old task and creates the reverse task
- [ ] `TestExecuteActionSuspend`: executing suspend sets run_period to 0
- [ ] `TestExecuteActionResume`: executing resume restores the scheduled run period
- [ ] `TestExecuteActionFailoverRemote`: executing failover remote destroys local, promotes clone, creates reverse replication
- [ ] `TestCreateRemoteVolume`: creates a dataset clone on the remote TrueNAS appliance
- [ ] `TestReplicationProtoRegistered`: the replication service is registered on the controller's gRPC server
