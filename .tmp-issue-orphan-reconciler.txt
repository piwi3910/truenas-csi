## Problem

Dell's CSM for Resiliency includes `podmon`, a component deployed as a sidecar in CSI controller and node pods that validates host connectivity and monitors pod health to ensure CSI operations are cleaned up on pod death. This driver already has issue #1 for the node-side health checker, but it does not cover the controller-side failure protection.

On the controller side: the controller is a Deployments pod. If it dies mid-operation (while waiting for a TrueNAS job, mid-provisioning, mid-delete), the operation is abandoned entirely. No cleanup happens — the volume exists on TrueNAS in a half-created state, the CSI controller never finishes the operation, and kubelet retries indefinitely.

This differs from Dell's approach: their Podmon sidecar calls `NodeUnpublishVolume`, `NodeUnstageVolume`, and `ControllerUnpublishVolume` on the local CSI socket when it detects the primary pod died unexpectedly. Our controller has no such mechanism.

## Design

An orphan reconciler that runs inside a separate deployment of the TrueNAS CSI sidecar, or co-located in the same controller pod as a sidecar.

### Option 1: Orphan reconciler (controller-side)

The controller runs an orphan reconciler that:

- Periodically (every 60 seconds) calls `pool.dataset.query` to find all datasets marked with `io.truenas.csi:managed`
- Compares this list against the in-cluster CSI volumes (tracked via PV/PVC ownership)
- For each volume that exists on TrueNAS but has no corresponding PV in the cluster, triggers cleanup (or at minimum, logs the discrepancy)
- For each volume that exists on TrueNAS and is in-provisioning (sparse zvol exists but NFS target/iSCSI extent not created), completes the provisioning or marks the volume as orphaned

### Option 2: Podmon sidecar (already started by another AI coder)

See issue #2 below for the Podmon sidecar component.

## Acceptance Criteria

- [ ] `TestOrphanReconcilerDetectsUnlinkedVolume`: a dataset exists on TrueNAS with the ownership marker but no corresponding PV -> reconciler detects it
- [ ] `TestOrphanReconcilerSkipsLocalVolumes`: a dataset exists on TrueNAS AND has a corresponding PV -> reconciler does not touch it
- [ ] `TestOrphanReconcilerInPlaceOfSidecar`: the reconciler runs as a separate goroutine within the controller, sharing the same backend client
- [ ] Integration: deploy the driver, delete the PVC while the controller pod is killed; assert reconciler detects and cleans up the orphan
