# Pool reservation: report free capacity minus reserved (not pool free)

## Problem

Dell's CSM drivers report pool capacity as `pool_free - reserved`. This reserves space for system metadata, snapshots, and replication targets so that the CSI driver doesn't consume the entire pool and leave no breathing room for the platform.

Our CSI driver reports the full pool free space in `NodeGetCapacity`. If a user creates PVCs up to the reported capacity, the pool fills past the safe threshold — snapshots can fail to replicate, TrueNAS system datasets fill up, and the platform degrades.

Additionally, TrueNAS reserves up to 50 GiB for snapshots that already exist on the pool (not our CSI volumes). Users see 2 TiB free when they can actually only create ~1.95 TiB of new data.

## Design

Add a `reservation_size` and `reserved_capacity` configuration option to the driver.

### StorageClass parameter

Add a `reserved_bytes` StorageClass parameter. If set, the driver subtracts this from the reported capacity and uses it as a hard cap for provisioning (rejects PVCs that would go over the cap).

```yaml
storageClasses:
  - apiVersion: storage.k8s.io/v1
    kind: StorageClass
    provisioner: truenas.csi.watteel.com
    parameters:
      reserved_bytes: "53687091200"  # 50 GiB
```

### Pool reservation

The `reserved_capacity` in `NodeGetCapacity` should be:
- `50 GiB` (the TrueNAS system snapshots reservation)
- Plus `reserved_bytes` from the StorageClass (if set)
- Plus any existing TrueNAS snapshots on the pool (queried at startup, not dynamically tracked)

```go
func (n *node) NodeGetCapacity(ctx context.Context, req *csi.NodeGetCapacityRequest) (*csi.NodeGetCapacityResponse, error) {
    statbuf, err := n.statfs(n.cfg.PoolPath)
    if err != nil {
        return nil, err
    }

    total := statbuf.Length * statbuf.Blocks
    available := statbuf.Bavail * statbuf.Bsize

    // Subtract reserved capacity (snapshot reservation + user reservation)
    reserved := n.cfg.SnapshotReservation + n.cfg.ReservedCapacity

    return &csi.NodeGetCapacityResponse{
        Capacity: available - reserved,
    }, nil
}
```

### Controller expand volume (capacity cap)

When creating a volume, the controller checks that adding the new volume won't exceed the pool free minus reserved:

```go
func (c *controller) CreateVolume(ctx context.Context, req *csi.CreateVolumeRequest) (*csi.CreateVolumeResponse, error) {
    requested := req.GetCapacityRange().GetRequiredBytes()

    poolFree, reserved := c.getPoolCapacity(ctx)
    available := poolFree - reserved

    if requested > available {
        return nil, status.Errorf(codes.ResourceExhausted, "requested %d bytes exceeds available pool capacity %d", requested, available)
    }

    // ... proceed with create ...
}
```

### TrueNAS reserved capacity

TrueNAS manages its own reserved capacity for snapshots. We query it at startup and at each capacity check:

```go
func getSnapshotReservation(ctx context.Context, client *truenas.Client) (int64, error) {
    // Query all snapshots on the pool, sum their sizes
    var total int64
    for _, snap := range snaps {
        total += snap.reference
    }
    // TrueNAS default is 50 GiB
    defaultReservation := int64(50) * 1024 * 1024 * 1024
    if total > defaultReservation {
        return total, nil
    }
    return defaultReservation, nil
}
```
